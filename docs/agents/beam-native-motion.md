# Beam texture motion — Studio 0.26.0

Presets are only starting documents. Author an own PNG, import it using `assets.import`, and use it on a saved `beam` layer. Studio 0.26 adds optional atomic `nativeMotion` through UI, CLI and all existing WebMCP operations. It produces a real animated native texture atlas. It is **not yet qualified in NWN**; a consumer task performs game integration and testing.

```json
[{"type":"layer.set","layerId":"beam","values":{
  "segments":2,"radius":0,"lightningScale":0,
  "nativeMotion":{"phase":"flow","direction":"target-to-source","fps":16,"pulseWidth":0.25,"fit":"alpha-bounds"}
}}]
```

Use `nwn-vfx --json changes preview --project ID --expected-revision N --input-file PATH` before `changes apply` with the same revision, file and a stable `--idempotency-key`. In a granted browser tab, call `studio.view.inspect`, then `studio.changes.preview/apply` with `{viewSessionId,input:{projectId,expectedRevision,changes},idempotencyKey}`. Read the discovered schema. No extra tool or owner credential is needed. `nativeMotion:null` removes the setting; legacy `flow` then resumes its preview-only meaning. It never silently becomes native motion.

The UI **Faza atlasu beama** explicitly sets two points and zeros Lightning radius/scale. The operation requires those exact values: Linked maps the entire atlas cell to **each** geometric segment, so a sixteen-point bolt would repeat the wipe. The nativeMotion profile has one straight quad. `source` means the EffectBeam source/caster; `target` means the other endpoint/victim. Their editor coordinates remain preview-only. EffectBeam supplies moving native endpoints.

| Parameter | Contract |
|---|---|
| `phase` | `flow`, `opening`, `closing` |
| `direction` | Flow pulse only: `target-to-source` or `source-to-target` |
| `fps` | Integer 1–60, positive native FPS controller |
| `pulseWidth` | 0.02–1 of the **whole span**, flow pulse only |
| `fit` | `source` preserves the whole image; `alpha-bounds` explicitly crops the bounding rectangle of pixels with alpha > 0 |

Source PNG X runs from source to target. The crop is stretched to span length and full authored width, then remapped to native Linked V along the beam and U across it. Source assets remain byte-identical. The derived atlas is 1024×1024 RGBA, four columns/four rows, sixteen 256×256 cells. Resampling reduces by area and enlarges bilinearly per axis, in linear sRGB with premultiplied alpha. Generated bytes are deterministic. Padding removed, crop rectangle, source/atlas hashes and filtering are recorded in `beam.json`. No automatic contrast, recolor, alpha inference or source replacement. A fully transparent image cannot use `alpha-bounds`.

`flow` multiplies alpha by a moving raised-cosine pulse over a 25% baseline. One pulse traverses the normalized span per sixteen-frame cycle. It is **not metres/second independent of distance**. `opening` reveals source → target; frame 0 is transparent and frame 15 contains the entire fitted source. `closing` erases target → source; frame 0 is full and frame 15 transparent. Opening/closing have no additional pulse. Direction/pulseWidth stay saved for returning to flow but do not affect those two phases. Generate separate candidates for phase switching.

For nativeMotion only, `width` is the full ribbon width: exported sizeStart/Mid/End = width/2. The recovered Linked renderer adds/subtracts size.x on each side. Historical 0.25 beams without nativeMotion retain their exact older size/resource encoding. Native visual width, camera-facing orientation and UV direction still require observation.

## Timing and the consumer boundary

The native controls are `update Lightning`, `render Linked`, `xgrid=ygrid=4`, `frameStart=0`, `frameEnd=15`, `fps=<saved>`, `birthrate=2`, `loop=0`, radius/scale 0. Atlas repetition is independent of emitter `loop`; no empty model animation is invented. `progfx` Type 7 uses the model and its animation selector (stock `cast01`). This candidate has no authored cast01 animation: texture FPS supplies motion.

**Every phase repeats. No automatic hold-last, stop, deletion, phase chaining or cessation is exported.** Consumer scripts must apply/remove/swap the exact candidate effects. Removing an effect does not trigger the closing atlas automatically.

| Saved FPS | Ideal cycle | Final-frame start | Planned final-frame interval |
|---|---|---|---|
| 16 | 1 s | 0.9375 s | [0.9375, 1) s |
| 15 | 1.0666667 s | 1 s | [1, 1.0666667) s |
| 30 | 0.5333333 s | 0.5 s | [0.5, 0.5333333) s |

These intervals are **not guaranteed native safe switch times**. The recovered renderer advances after elapsed time reaches `1/fps`, then discards fractional remainder. At ideal 60 Hz, 16 FPS can therefore act like 15 FPS; real draw cadence and effect application also matter. Preview samples ideal `floor(time*fps)%16`. Consumer must measure direction/cadence, then choose a transition inside the observed last frame. There is no honest fixed safe boundary before that observation. Metadata gives numeric `frameCount`, `fps`, `cycleSeconds`, `finalFrameStartSeconds`, `transitionWindowSeconds`, repeat/stop flags and `nativeCadenceVerified:false`.

No endpoint glows in this profile. Stock models show a source-root Fountain and a reattachable target reference; this is a separate extension after this beam path is tested. No engine lifetime/endpoint assumption is hidden in the source PNG.

## Compatibility, delivery and evidence

Adding nativeMotion or its lock promotes only the new revision to document 17 / project ZIP 12 / minimum Studio 0.26.0; clients declare `X-NWN-VFX-Document-Schema:17`. Clients at 16 or below fail before committing new motion fields, including null reset. Old documents, project heads and artifacts are not rewritten. Atomic field lock, layer lock, AI pause, project-scoped grants, revisions, stable retry and undo remain enforced. Preserve pending beam raw text in `meshEditorDrafts[layerId].beam`; a fresh tab is needed after update. All 49 WebMCP tools stay available.

ASCII/binary candidate exporter 0.26 is used for documents with nativeMotion. `beam.json` v2 carries the actual derivative and controller evidence. `vfx-integration.json` v4 supplies per-layer timing and settings, null table rows for consumer allocation and `nativeFlowControl:true` meaning **baked texture motion**, not particle velocity. Older beams retain integration v3/exporter0.25. PNG/WebM metadata uses `beamNativeMotion`. Read job artifacts through bounded `artifacts.read` chunks, verify chunk and complete SHA256/size, and hand off immutable revision/model hashes.
