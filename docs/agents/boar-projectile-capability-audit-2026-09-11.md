# Boar projectile: capability and engine audit

2026-09-11. Read-only inspection of Studio 0.30.1, consumer v2 exports from
Studio 0.28, Toolset decompilation and retail client instructions. No source
project, accepted candidate, application implementation or running service was
changed. No Toolset or NWN executable was launched.

## Decision

**The complete requested effect is not currently supported by Studio:** one
boar head travelling between actual caster/target chest attachments, with two
repeatable lateral curves defined relative to their connecting direction, and
an orange cutting trail generated by that head's motion.

Current mesh animation and trail paths contain local coordinates. Current
finite beam flow moves sprite particles between endpoints; it cannot carry
the boar mesh. A new preset or a mirrored local animation cannot close this gap.

The narrowest candidate for further source verification is **P2P Bezier with
a Chunk model payload**, extending the existing beam attachment mechanism.
This is a research direction, not an admitted export profile. Before building
it, establish exactly-one emission, a source-to-target lateral coordinate
frame, heading, both chest attachments and nested trail lifecycle. Type10 is
an alternative for a real moving model, but the currently audited path-4
contract is straight and does not satisfy LEFT/RIGHT curves.

## Exact consumer files

Inspected both `native/v2/{left,right}/studio-candidate` directories under
`C:/Projects/the last city/assets/vfx/berserker/glowa-dzika`.

- Both documents use schema 20, lifecycle `impact`, duration 1.75 seconds.
- Each has one head mesh and three trails. Head position and orientation each
  have 57 keys; each trail has 29 path samples. The variants really do differ
  in their interior head position/orientation keys and trail paths.
- The head begins at local `[-2.35, 0, 1.159331]`. The orange trail runs from
  `[-2.56, 0, 1.42]` to `[-0.61, 0, 1.42]`; its lateral bounds are approximately
  `[-0.007141, 0.907141]` for LEFT and `[-0.907141, 0.007141]` for RIGHT.
- Both source MDLs contain `newanim impact` and four static `alpha 0` mesh
  nodes. Visibility depends on the animation's alpha controllers. This is
  consistent with the existing FnF lifecycle, not evidence of an alpha defect.

These are actual different local curves, but neither document expresses a
relationship to two live creatures. Reusing them beneath a moving owner would
combine owner travel with the already baked local travel. Reusing their whole
trail beneath that owner would also move the authored trail geometry with it.

**Toolset:** `C:/Projects/New Folder/export/decompiled_all.c`, SHA256

**Retail Linux client:** SHA256
`6d19c39bc646af5ddbc333ff31797a4acd9019506bcb45ef1b93b1bd5925e700`.
Fresh read-only disassembly is saved in
`C:/Projects/New Folder/boar-projectile-audit-2026-09-11`.

- `ChunkyParticle` constructor, `0x4abf93..0x4abfa2`, passes the emitter's
  payload model reference to `NewCAurObject` and stores a separate model.
- `ChunkyParticle::initialize`, `0x4abf33`, explicitly loads the string
  **`impact`**; `0x4abf3d..0x4abf47` dispatches Gob vtable slot `+0x38`, resolved
  as `Gob::PlayAnimation(char const*, float, int, float)`. Therefore a Chunk
  payload's `impact` is source-backed. It must not be renamed to `cast01`
  simply because its parent uses a beam animation.
- `PartEmitter::Initialize`, `0x4aae2e`, selects the P2P Bezier movement
  function. Existing reverse audit proves live target lookup and cubic
  age/life progress. These facts alone do not prove the combined single-Chunk
  dispatch path or orientation.
- `CNWCProjectile::SetAnimation`, `0x7f3960..0x7f39c2`, uses a numeric animation
  selector. This is a different dispatch contract. This inspection does not
  establish that a Type10 model automatically receives `impact`, `cast01`,
  or `default`; do not guess one or force static alpha to hide the question.

**Retail Windows Type10:** the existing July 18, August 13 and August 17
audits bind client SHA256
`3b7cb1252e0edb2ce22d7971f333aade027039ae30a45b4bc64732c3e6bec73a`.
They establish one moving owner, `Param4=4` as path style, linear travel and
owner release at arrival. `Param5=log` uses deterministic
`trunc(distance / (1.5 + 3*logf(distance)) * 1000)` milliseconds, **not RNG**.
Nonzero orientation modes remain incompletely mapped; distances at/below
`exp(-0.5)` have an unproven timing boundary. Neither stock path names nor
the log timing formula establish a deterministic LEFT/RIGHT curve.

The recovered Toolset P2P controls are scalar distances along source and
target forward vectors: `P1=S+sourceForward*h2`,
`P2=T+targetForward*h3`. They are not arbitrary world-space control points.
Negating the handles does not by itself define left/right relative to S→T
when creature facing changes. A proposed attachment/basis must be traced,
including target-reference orientation, before exposing such controls.

## Public operations available today

Examples below use existing operation inputs; they are not executed by this
audit. Select the intended instance, inspect permissions and preserve explicit
revisions/idempotency keys. WebMCP uses the `studio.` operation prefix.

```json
{"operation":"projects.fork","input":{"projectId":"tlc-boar-left-v2","revision":2,"name":"Boar projectile research"},"idempotencyKey":"boar-projectile-research-fork-001"}
```

`projects.create` with `{ "preset": "empty", "lifecycle": "beam" }` and a
name creates a beam project. `meshes.importObj` and `assets.import` author
custom payload assets in an eligible mesh project. `changes.preview` /
`changes.apply` submit `layer.add`, `layer.set` and `project.set` operations.
`preview.request`, `candidate.build`, `jobs.get` and `artifacts.get` render,
build and retrieve an exact revision. For an existing eligible beam document:

```json
{"operation":"candidate.build","input":{"projectId":"PROJECT","revision":2,"profileId":"nwn-ee-beam-binary-experimental-v1","modelName":"boar_research"},"idempotencyKey":"boar-research-build-001"}
```

This builds only currently admitted beam content. There is **no valid public
operation sequence for the complete requested projectile today**. Supplying
unknown Chunk/curve fields or appending a mesh to a finite beam is not a
supported workaround. There is no reason to patch candidate MDL/2DA files
behind Studio's exporter or alter the consumer's saved project.

## Required extension and completion criteria

1. Recover the native combined path for exactly one Chunk, its body-node
   endpoints and its direction frame. Decide whether the two curve variants
   can be selected without RNG or actor-facing assumptions. If this cannot be
   established, stop that route with a precise unsupported capability.
2. Add a versioned model-payload/trajectory contract, shared by UI, CLI and
   WebMCP. Preserve revision conflicts, locks, AI pause and immutable artifacts.
3. Export a centered payload with an explicit activation animation/static
   visibility policy and no baked inter-creature translation. Derive the head
   orientation from the recovered engine contract.
4. Bind trail emission to the moving head and define world-space retention,
   arrival and remaining-tail behavior. Existing local trail keys do not meet
   this requirement.
5. Verify the two actual head trajectories at several distances (e.g. 1, 3,
   8 m), world headings and creature facings; repeated casts must retain the
   signed lateral side, emit exactly one head and reach the chosen chest node.
   Include elevation, moving-target policy and short-distance handling.
6. Produce isolated preview/export/readback artifacts and a consumer handoff.
   The qualified consumer then verifies exact resources in NWN, including
   head/trail attachment and lifecycle. Export/readback and Studio tests alone
   never close native acceptance.

Only audit artifacts were written in this task; implementation and native
qualification remain open.
